GitHub Pages で無料サイトを
公開するまでの完全手順

⏱ 所要時間：30〜60分 💰 費用：¥0 🧩 難易度：初心者向け（ハマりポイント付き）

この手順書は実際につまずいた箇所も含めて記録した、リアルな体験ベースのガイドです。GitLabユーザーがGitHubを使う場合のUIの違いも補足しています。

準備
STEP 01

GitHubアカウントを作る・ログインする

すでにアカウントがある場合はスキップしてOK。

  • https://github.com にアクセス
  • 「Sign up」からアカウント作成（メールアドレスがあればOK）
  • ユーザー名はサイトのURLになるので慎重に決める
ℹ ユーザー名を yudo-dev にした場合、サイトのURLは https://yudo-dev.github.io/ になります。
STEP 02

リポジトリを作る（名前に注意！）

右上の「＋」→「New repository」をクリック。

  • Repository name に ユーザー名.github.io と入力（例：yudo-dev.github.io）
  • 「Public」を選ぶ
  • 「Create repository」をクリック
⚠ つまずきポイント
リポジトリ名が ユーザー名.github.io と完全一致しないと、URLが ユーザー名.github.io/リポジトリ名/ という二重URLになってしまう。後から Settings → General → Rename で変更可能。
ファイルを作ってpushする
STEP 03

index.html を作る

ローカルの作業フォルダに index.html を1枚作る。これだけでサイトが成立する。

<!-- 最小構成のindex.html -->
<!DOCTYPE html>
<html lang="ja">
<head><meta charset="UTF-8"><title>My Site</title></head>
<body><h1>こんにちは！</h1></body>
</html>
✦ ファイル名は必ず index.html（小文字）にすること。大文字だと表示されない場合がある。
STEP 04

GitHubにpushする

ターミナル（PowerShell可）を index.html があるフォルダで開いて実行。

$ git init
$ git add index.html
$ git commit -m "初回：index.html追加"
$ git branch -m master main # ブランチ名をmainに統一
$ git remote add origin https://github.com/ユーザー名/ユーザー名.github.io.git
$ git push -u origin main --force
⚠ つまずきポイント
ターミナルを index.html があるフォルダとは別の場所で開いていると「nothing to commit」になる。pwd でどこにいるか確認してから実行する。
error: remote origin already exists が出た場合は git remote -v で確認し、必要なら git remote set-url origin [URL] で上書き。
pushしたのにGitHubのCodeタブにファイルが見えない場合は、ブランチ名がずれている可能性あり。main ブランチにpushできているか確認。
GitHub Pages の設定
STEP 05

GitHub Pages を有効にする

  • GitHubのリポジトリページを開く
  • 上部タブの「Settings」をクリック
  • 左サイドバーの「Pages」をクリック
  • Branch のドロップダウンを main に変更
  • フォルダは / (root) のまま
  • 「Save」をクリック
ℹ Saveを押した直後は「GitHub Pages is currently disabled」と表示されることがある。1〜2分待ってページをリロードすると「Your site is live at...」に変わる。
⚠ つまずきポイント
Branch のドロップダウンが選べない → リポジトリにファイルがまだpushされていない状態。STEP 04 を先に完了させる。
GitLabに慣れているとUIの場所が全然違うので迷いやすい。「Settings」は上部タブの右端にある。
DONE

サイトにアクセスして確認

1〜2分待ってからブラウザでアクセスする。

# URLの形式
https://ユーザー名.github.io/
✦ URLが ユーザー名.github.io/リポジトリ名/ になっている場合はリポジトリ名が間違っている。Settings → General → Repository name で ユーザー名.github.io に修正する。
🎉
公開完了！

TIPS

個人サイトのブランチ戦略

趣味・個人サイトなら main 1本で運用するのが最もシンプルでおすすめ。

# シンプル運用（おすすめ）
main ──── 直接コミット → 即公開
 
# リニューアル時だけブランチを切る
main ────── 公開中のサイト
└── develop ── 作業中（完成したらmainにマージ）
✦ 最初からdevelopブランチを切ると毎回マージが必要になり、更新が億劫になりがち。「大幅に変えたい！」と思ったタイミングで切るのがちょうどいい。
