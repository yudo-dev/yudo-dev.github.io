▶ GUIDE v1.0 — 2026.05.20

Jekyll で GitHub Pages を動かす
カスタムデザイン完全手順書

⏱ 所要時間：1〜2時間 💰 費用：¥0 🖥 対応OS：Windows 10 / 11 🧩 難易度：初心者向け（つまずき対策付き）

この手順書は実際にやってつまずいた箇所も含めて記録した、リアルな体験ベースのガイドです。

完成するもの：記事を _posts フォルダに追加するだけでトップページに自動表示される、オリジナルデザインのブログサイト。

前提：GitHubアカウントとリポジトリ（ユーザー名.github.io）がすでにある状態から始めます。
GitHubの基本セットアップは こちらの手順書 を先に読んでください。

Phase 1 — Ruby と Jekyll のインストール
STEP 01

Ruby をインストールする

Jekyll は Ruby という言語で動いています。まず Ruby をインストールします。

  • https://rubyinstaller.org/downloads/ を開く
  • 「Ruby+Devkit」の中から 太字になっている推奨版（例：Ruby+Devkit 3.3.x (x64)）をダウンロード
  • インストーラーを起動 → 「Next」を押し続けてインストール
  • 最後に「Run 'ridk install'...」のチェックが入っていることを確認して「Finish」
  • 黒い画面（コマンドプロンプト）が開くので、1 を入力して Enter → 完了したらもう一度 Enter で閉じる
ℹ インストール後、PowerShell を新しく開き直してから次のステップへ進んでください。開いたまま続けると Ruby が認識されないことがあります。

インストールできているか確認：

PS> ruby -v
ruby 3.3.x ... # バージョンが表示されればOK
STEP 02

Jekyll と Bundler をインストールする

PowerShell で以下を実行します。

PS> gem install jekyll bundler
... 数分かかります ...
Successfully installed jekyll-4.4.x

完了したらバージョン確認：

PS> jekyll -v
jekyll 4.4.x
⚠ つまずきポイント
「gem が認識されない」→ PowerShell を管理者として実行して再度試す。または Ruby のインストール後に PowerShell を開き直す。
インストールがやたら遅い → ネット接続を確認。rubygems.org につながっていれば数分で終わるので待つ。
Phase 2 — Jekyll サイトのセットアップ
STEP 03

作業フォルダで Jekyll を初期化する

サイトのファイルが入っているフォルダ（例：hp_work）を PowerShell で開きます。

# フォルダを開く（パスは自分の環境に合わせて変更）
PS> cd C:\Users\ユーザー名\Documents\hp_work

Jekyll の初期ファイルを生成します。すでにファイルがある場合は --force を付けます。

PS> jekyll new . --force --skip-bundle
ℹ --force を付けると既存ファイルを上書きしません（新しいファイルだけ追加）。--skip-bundle は次のステップで手動でインストールするため付けています。
STEP 04

_config.yml を設定する

生成された _config.yml をテキストエディタ（メモ帳でもOK）で開き、以下のように書き換えます。

_config.yml
title: MY WORLD # サイトのタイトル
description: 活動記録ブログ # サイトの説明
url: "https://ユーザー名.github.io"
baseurl: ""
 
plugins:
- jekyll-feed
✦ url の「ユーザー名」は自分の GitHub ユーザー名に変えてください（例：https://yudo-dev.github.io）。
STEP 05

Gemfile を確認して bundle install する

Gemfile が以下の内容になっていることを確認します（jekyll new で自動生成されます）。

Gemfile（確認用）
gem "jekyll", "~> 4.4.1"
gem "minima", "~> 2.5"
 
group :jekyll_plugins do
gem "jekyll-feed", "~> 0.12"
end

確認できたら依存ライブラリをインストールします：

PS> bundle install
... インストール中 ...
Bundle complete!
Phase 3 — カスタムレイアウトの作成
STEP 06

_layouts フォルダとレイアウトファイルを作る

Jekyll は _layouts フォルダの HTML を「ページの枠組み」として使います。ここを自分でカスタマイズすることで、オリジナルデザインのサイトが作れます。

ファイル構成のイメージ

hp_work/
├── _layouts/ # ← 新しく作るフォルダ
│ ├── default.html # 全ページ共通の枠組み（ヘッダー・フッター等）
│ └── post.html # 記事ページ専用の枠組み
├── _posts/ # ブログ記事を置くフォルダ
├── _config.yml
└── index.html # トップページ（記事一覧）

① _layouts/default.html を作る

_layouts フォルダを作り、その中に default.html を作ります。これが全ページで使われる「外側の枠」です。

内容は自分のデザインを書いた HTML ファイルで、本文が入る場所に {{ content }} を書くのがポイントです。

_layouts/default.html（構造イメージ）
<!DOCTYPE html>
<html>
<head>
<title>{{ page.title }} — {{ site.title }}</title>
<style> ... 自分のCSS ... </style>
</head>
<body>
<header> ... ヘッダー ... </header>
 
{{ content }} <!-- ← 各ページの内容がここに入る -->
 
<footer> ... フッター ... </footer>
</body>
</html>

② _layouts/post.html を作る

記事ページ専用のレイアウト。default.html を継承するため、先頭に以下を書きます。

_layouts/post.html
---
layout: default
---
<main>
<h1>{{ page.title }}</h1>
<div class="post-body">{{ content }}</div>
<a href="/">← TOPに戻る</a>
</main>
STEP 07

index.html を更新して記事を自動一覧表示する

index.html の先頭に layout: default を宣言し、記事一覧表示に Liquid テンプレートを使います。

既存の <!DOCTYPE html> から </html> までの全体を削除し、以下の構成に書き換えます。

index.html（構造）
---
layout: default # default.html を使う宣言
---
<main>
 
<!-- 記事ループ -->
{% for post in site.posts %}
<div class="card">
<a href="{{ post.url }}">
<h3>{{ post.title }}</h3>
<p>{{ post.excerpt | strip_html | truncate: 100 }}</p>
<div>{{ post.date | date: "%Y.%m.%d" }}</div>
</a>
</div>
{% endfor %}
 
</main>
✦ {% for post in site.posts %} が Liquid テンプレート構文です。_posts フォルダのファイルを自動で読み込み、繰り返し表示します。
STEP 08

ローカルで動作確認する

GitHub に push する前に手元で確認します。

PS> bundle exec jekyll serve
Server address: http://127.0.0.1:4000/
Server running... press ctrl-c to stop.

ブラウザで http://localhost:4000 を開くとサイトが表示されます。
ファイルを保存するたびに自動で更新されます（ページをリロードすれば反映）。

確認が終わったら Ctrl + C でサーバーを停止します。

ℹ bundle exec jekyll build はファイルを _site フォルダに生成するだけ。jekyll serve はサーバーも起動してブラウザで確認できます。
⚠ つまずきポイント
「Layout 'xxx' requested in yyy does not exist」という警告 → 指定されたレイアウトファイルがない。_layouts フォルダのファイル名を確認する。
デザインが崩れている → index.html に <!DOCTYPE html> や <html> タグが残っていると二重になる。<main> 〜 </main> の内容だけ残して削除する。
Phase 4 — GitHub Actions で自動公開する
STEP 09

GitHub Actions のワークフローファイルを作る

GitHub Pages で Jekyll 4 を動かすには、GitHub Actions を使う必要があります。
以下のフォルダとファイルを作ってください。

.github/
└── workflows/
└── jekyll.yml
.github/workflows/jekyll.yml（内容をそのままコピー）
name: Deploy Jekyll site to GitHub Pages
 
on:
push:
branches: ["main"]
workflow_dispatch:
 
permissions:
contents: read
pages: write
id-token: write
 
jobs:
build:
runs-on: ubuntu-latest
steps:
- uses: actions/checkout@v4
- uses: ruby/setup-ruby@v1
with:
ruby-version: '3.3'
bundler-cache: true
- uses: actions/configure-pages@v5
id: pages
- run: bundle exec jekyll build --baseurl "${{ steps.pages.outputs.base_path }}"
env:
JEKYLL_ENV: production
- uses: actions/upload-pages-artifact@v3
 
deploy:
needs: build
runs-on: ubuntu-latest
environment:
name: github-pages
url: ${{ steps.deployment.outputs.page_url }}
steps:
- uses: actions/deploy-pages@v4
id: deployment
STEP 10

Gemfile.lock に Linux プラットフォームを追加する

Windows で作った Gemfile.lock は Windows の情報しか持っていません。GitHub Actions は Linux で動くため、このままだとビルドが失敗します。以下のコマンドで Linux を追加します。

PS> bundle lock --add-platform x86_64-linux
Writing lockfile to .../Gemfile.lock
⚠ このコマンドを忘れると GitHub Actions で「Your bundle only supports platforms ["x64-mingw-ucrt"]」というエラーが出ます。必ず実行してから push してください。
STEP 11

GitHub Pages の Source を GitHub Actions に切り替える

GitHub のリポジトリページで設定を変更します。

  • リポジトリの Settings タブを開く
  • 左サイドバーの Pages をクリック
  • 「Build and deployment」の Source を Deploy from a branch から GitHub Actions に変更
ℹ この設定を変えないと、ワークフローファイルを作っても GitHub がそれを使ってくれません。
STEP 12

全ファイルを git push して公開する

変更したファイルをすべてコミットして push します。

# 変更ファイルをステージング
PS> git add _layouts index.html 404.html .github _posts _config.yml Gemfile Gemfile.lock .gitignore
 
# コミット
PS> git commit -m "Jekyll化：カスタムレイアウト追加"
 
# push
PS> git push origin main

push 後、GitHub の Actions タブ を開くとビルドが走っているのが見えます。
緑のチェックマークになれば公開完了です（1〜2分かかります）。

⚠ つまずきポイント
Actions が赤くエラーになった → エラーのログを読む。「platform」に関するエラーは STEP 10 のコマンドを実行して再度 push。
Actions が緑でもサイトが古いまま → ブラウザのキャッシュをクリアしてリロード（Ctrl + Shift + R）。
🎉
Jekyll サイト公開完了！
https://ユーザー名.github.io/

記事を追加するたびに自動でトップページに一覧表示されます。

Bonus — 記事の書き方
TIPS

新しい記事を書いて公開するまで

ファイル名のルール

_posts フォルダの中に以下の形式でファイルを作ります。

YYYY-MM-DD-タイトル.md
 
# 例
2026-05-20-my-first-post.md
2026-06-01-summer-diary.md

記事ファイルの書き方

ファイルの先頭に「Front Matter」と呼ばれる設定を書き、その後に本文を書きます。

_posts/2026-05-20-my-first-post.md
---
layout: post # 固定（変えない）
title: "はじめての記事" # 記事タイトル
date: 2026-05-20 12:00:00 +0900
categories: まなぶ # カードのタグ（つくる / まなぶ / きろく など）
tag_color: blue # カードの色（yellow / blue / pink）
---
 
ここから本文をMarkdownで書きます。
 
## 見出し2はシャープ2つ
### 見出し3はシャープ3つ
 
普通の文章はそのまま書くだけです。
空行を入れると段落が変わります。
 
- リスト項目1
- リスト項目2

書いたら push するだけ

PS> git add _posts/2026-05-20-my-first-post.md
PS> git commit -m "記事追加：はじめての記事"
PS> git push origin main

1〜2分後にサイトのトップページに新しい記事カードが表示されます。

✦ 記事を公開したくない場合はファイル名の日付を未来の日付にするか、_drafts フォルダ（下書き用）に入れておけばビルドに含まれません。
